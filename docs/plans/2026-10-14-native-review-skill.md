# CLI 原生评审 skill 接入

## 目标

后台评审由 Codex CLI 显式调用原生 skill，按改动规模和风险分级；保留完整
Head 读取、结果校验、发布去重和人员交接。使用现有岗位模型和推理强度。

## 接入约定

- 原生入口为系统提供的 `dih-pr-review`，在每次调用目录的 `.agents/skills`
  注册；采用 `pr-review-tiering` 的后台适配流程，明确区别于原版 CE 全流程。
- 本机已安装的分级规则和 CE 审查视角作为技能资源读取，并记录内容摘要；
  不固定插件版本。缺少这些可选资源时明确记录实际覆盖，仍可使用内置评审流程。
- 技能及引用资料由受控只读 MCP 提供，避免依赖被策略拒绝的宿主文件命令。
- 中大型改动在 CLI 提供代理工具时使用有界的独立审查员；收齐结果后再合并。
  没有独立收据时必须说明覆盖限制，不得冒称 CE 或跨模型完整评审。
- CLI 只形成现有 WorkDecision，发布和分配由现有系统执行。技能不运行
  `gh pr review`，不执行仓库脚本或构建，不修改原仓库和用户配置。
- 非原生 CLI、非 Review 任务维持现有技能注入方式。

## 实现单元

### U1. 技能包与可信资源读取

增加原生入口和资源加载器；在 PR 只读端点提供技能文档，并校验入口完整读取。
验证资源缺失、路径及链接拒绝、摘要稳定和完整读取门禁。

### U2. 原生调用与岗位集成

只对原生 Review 在调用目录注册 skill，显式调用并按需启用代理工具；阻止环境
技能自动干扰。通过能力描述让岗位提示词不重复注入旧技能。清理只处理已知的
本次调用文件，保留未知残留和原生会话。

### U3. 验证、文档和运行检查

更新原生适配器及岗位集成回归；使用真实 CLI 和合成 PR 数据验证技能加载、
完整读取和结构化输出，不重复评审已交接的真实 PR。复核后本地提交、受管重启，
检查配置和真实运行状态。另行追踪 PR #24723 的自动修复状态。

### U4. 自身 PR 修复的检查续跑

修正 Git 镜像对合法含 `#` 分支名的误拒绝。仅对绑定当前 Head、已封存提案的
自动自身 PR 修复任务，在 inspect 成功后继续排入原任务并保留受信检查结果；
下一轮据此提出 modify/verify。失败、过期、手动检查及更新 Head 的结算规则保持。
保留 #24723 的失败记录，通过受管停止和独占写入租约重排原任务后验证。

### U5. 避免旧巡查覆盖自动修复

开启自动修复自身 PR 时，旧 PR 推进员工把 authored/address_review 留给现有
GitHub → 开发工程师通道；相关旧巡查作业保留为 superseded，重试不能重新派单。
真正手动派单、其他下一动作及关闭开关时的行为保持。对已误派给主控的 #24723，
用新鲜完整 GitHub 快照生成原生 observed 事件，经生产 routing.ingest/ledger.intake
恢复自动来源；不修改快照时间、不删除历史、不恢复旧执行 binding。

## 完成条件

- 原生技能真实加载、引用读取和输出有证据；相关回归通过。
- 原有发布、分配、取消、会话恢复及未知文件保留规则不被绕过。
- 记录实际分级及审查覆盖，不以技能加载成功代替评审完成。
- 文档、配置保留与部署检查完成。

## 运行验收

部署后检查配置版本及摘要保持、原生技能能力可见、确认历史和运行任务接口可读。
对自身 PR 观察原任务是否从检查继续进入修改/验证；以受控变更及原 PR 更新收据
作为完成依据。发现 Head 不一致、重复发布、会话丢失或失败结果被当成成功时停止
对应自动动作并保留任务及会话证据。初次真实任务结束后复核，维护人员负责验收。

- 真实账本、条件唤醒器和协调服务组合：新 Head 解除旧 Head 的已交付事实等待；
  原回执保留，重启后新 Head 的后续等待可唤醒。明确时间等待不会被跳过。
- 真实确认队列与自动 Review 发布器组合：Review 已完成、下游引用丢失且分配变化时，
  恢复原完成回执，发表次数保持一次。
- 自动修复的发布与交接分开持久化。真实请求服务、路由和账本覆盖重启、丢交接回执、
  旧 publication 证据恢复，以及内部复审完成和缺陷退回研发。
- Windows 固定资产使用真实进程验证隔离副本、受控环境、失败退出、超时、取消、
  子进程终止和新 runner 实例清理。真实执行器完成、恢复与导出覆盖原生身份凭据。
- Windows-only 生产装配不需要 Docker；表单可保存并读取 Windows 固定资产，
  内部复审报告与权威测试证据分开传给岗位。

## 独立复审后的修复

第一轮独立复审保留了 9 项有效发现，均补充失败用例后修复：

- 原生登录缓存仅在确有活跃调用时复用；空闲时能恢复登录或识别凭据丢失。
- 岗位预领取与直接代码任务使用同一 PR 实体键；授权会话仍保持隔离。
- 原生与非原生模型都在实际启动边界更新 running，容量等待不伪装为执行。
- 内部复审的完成与交接均要求完整读取；原始意见使用摘要绑定快照，不受最新评论截断影响。
- 执行凭据首写失败仍阻止启动；后续写失败保留有界批次，恢复后可重试，旧批次不覆盖新状态。
- Windows 测试从同用户进程改为 LPAC，使用实际令牌证明和 Job Object 后代约束。
- 确认停止后删除大副本；Windows 短时文件锁使用有限重试，仍失败则保留清理待办。
- Windows-only 表单不要求 Docker，并可添加、编辑、删除摘要绑定资源。

恢复验证覆盖非空运行凭据、损坏状态、原反馈快照与旧格式。损坏数据在任何迁移写入前
拒绝；合法旧格式与快照保留原字节。浏览器验证覆盖资源行增删和编辑索引变化。

## 内部复审与长评审接续

现场内部复审曾在模型启动前因来源身份不被读取器接受而耗尽次数。修补允许受信的
内部复审事件使用其精确绑定的 GitHub 账户与 Head 读取资料。只有完整历史证明每次
均为该读取失败、没有已执行动作，且原反馈、当前资料和执行权限再次验证通过，才
允许一次正常恢复；累计次数与封存预算保持不变。并发修改、权限变化、分页缺失和
重复恢复均保留阻塞。相关七套组合回归通过 754/754，干净源码发布包检查通过 19/19。
实际部署已观察到自动恢复、第四次领取和内部静态复审完成；没有独立审查结果，
因此不计作多视角深度评审或 GitHub 外部批准。

另一个真实长评审在内容不变时反复失效：完整 PR 资料的旧摘要包含观察时间，刷新
观察时间就改变摘要。用现场新资料仅还原旧观察时间，能够精确重建评审开始时的
旧摘要。修补保持原缓存格式和旧摘要不变，在上下文投影中另生成完整资料摘要。
任何来源集合、正文或线程已经截断时不生成该证明；短预览相同不能替代完整资料
相同。仅在精确 PR 身份与完整资料摘要一致、两份上下文摘要有效、观察时间向前
且其余输入完全相同时，允许提交前刷新观察回执。Head、Base、反馈、检查、权限、
接纳输入、未知字段和实际领取版本变化仍拒绝。

真实账本与公开上下文装配器的同图、无关图推进两例在代码修改前先复现失败；
修补后各提交一次交付。隐藏正文变化、全部来源截断标志、缺失或伪造证明、回退
时间、矛盾摘要和并发版本变化均覆盖拒绝且不写入。追加十一套集成回归通过
907/907，零失败和跳过；另补有效上下文摘要下业务事实值、名称及集合增删的拒绝
验证，关闭复审的非阻塞补测建议。没有重跑核心全量。长评审补丁的发布包检查和实际部署
结果另记私有凭据。

## 报告交付、正式复审与历史提交关系

实际多行评审报告通过编排意图校验，却被图交付摘要拒绝。用现场 4,948 字节、
21 个换行的正文复现旧校验失败，再验证修补后逐字保留。仅交付摘要接受正常换行、
回车和制表符；标识符及其他控制字符仍严格拒绝，16 KiB UTF-8 上限不变。
真实账本、图与岗位上下文的定向回归通过 148/148。

另外，外部 rereview 曾被分解为本地 text-report，不能触发 GitHub 发布。正式复审
必须要求 authoritative Review 交付，不能仅以本地报告验收或完成主任务。旧的错误
报告先退回，再由正常控制取消已结算子任务；仅当旧错误任务全部取消且没有正式
任务时，允许用新子任务键重建。历史交付、失败次数和发布幂等约束保持不变。
集成验证走真实岗位决策、台账、确认队列、自动发布器和证据服务；隔离 GitHub
执行器代替外部写入。真实 PR 是否发布仍须以远端 Review 及本地结算凭据验收。

研发接续曾把当前来源失效套用到所有历史观察，跳过已经接纳的 A→B 提交关系，
导致后续独立来源 B 误被封锁。修补仅保留新鲜、已接纳且因果连续的历史关系，
不赋予失效来源执行权限或当前事实权限，同时保留有效目标观察的时间门槛，来源
退出不能把原先被拒绝的旧观察变成可执行。真实公共台账先失败后通过，相关回归
通过 420/420。未知 Head、缺失或拒绝的关系、不可用目标、旧格式降级、过期观察
和隔离状态均保留拒绝。现场只读副本确认 #24610 的权威可正确指向 tester 的
8330…；生产接续仍交给正常对账。#24615 缺失关系与 #24675 旧清理证明缺失不被
这项修补绕过。以上为定向验证，未重跑核心全量。
